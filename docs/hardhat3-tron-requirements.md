# Hardhat 3 TRON compatibility requirements

Hardhat 3 support will reuse the existing Hardhat 2 TRON transport, ethers facade and Docker TRE behavior. Framework registration and connection ownership will have separate adapters. The change extends the existing integration; it does not replace the transaction stack or change Hardhat 2 defaults.

This document supplements HH3-01 through HH3-08 in the external Sunhat design document. It governs the remaining TRON implementation after the verified EVM integration and native TRE probe. The [development plan](hardhat3-tron-development-plan.md) records stage gates and review evidence.

## Delivery boundary

The baseline is TypeScript, Mocha and ethers on real TVM, with existing Hardhat 2 and Foundry behavior preserved. The plugin is delivered through the public `@sun-protocol/sunhat/hardhat3-tron` subpath in the Sunhat artifact (`sunhat/hardhat3-tron` when installed through the generated npm alias). Framework and TRON dependencies belong to the consumer project; optional peers must accept existing Hardhat 2 consumers and must not install a framework or raise the CLI production minimum. R1 freezes exports, exact consumer dependencies and artifact paths; R3 verifies their installation. Ordinary TRE acceptance covers compiler identity, deployment, state, events, native receipts, address conversions and Energy/Bandwidth. Patched-node helpers have a separate capability matrix and test entry; an unavailable patched artifact is a reported verification gap, not a passed test.

Solidity tests, coverage, forks and upstream EVM-only helper behavior require their own acceptance evidence. Proxy upgrade tooling is not implicitly made Hardhat 3 compatible by the network adapter.

Repository content and review records use English. Changes follow the local TypeScript skill, including validation at external input boundaries and preservation of primary errors during cleanup.

## Inherited capability acceptance matrix

Every row must retain the Hardhat 2 baseline. The Hardhat 3 column describes required adaptation, not an existing implementation. All H3 verification states start as pending. Basic transaction support may be reported separately, but complete inherited-function compatibility requires evidence for every applicable row; a missing patched artifact leaves that gate incomplete.

| Capability                                                     | Required Hardhat 3 behavior                                                                                                       | Node requirement                                  | Initial H3 evidence                       |
| -------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------- | ----------------------------------------- |
| Deploy, read, mutate, events, receipts, native value/fee units | Reuse the ethers facade and native runtime with scoped state and explicit original fields                                         | Ordinary TRE                                      | Native TronWeb probe only; facade pending |
| `autoStartOnTest`, `autoStartOnCompile`, `autoStartOnNode`     | Preserve explicit policies through H3 task/connection hooks                                                                       | Ordinary TRE                                      | Pending                                   |
| `keepRunning`, external-node reuse, persistent node task       | Preserve ownership and keep-running behavior; never terminate reused services                                                     | Ordinary TRE                                      | Pending                                   |
| Snapshot/revert and `loadFixture`                              | Connection-scoped helpers preserve restoration and snapshot invalidation                                                          | Patched TRE                                       | Pending                                   |
| Mine/time control                                              | Reuse supported native cheatcodes; explicit capability errors on ordinary TRE                                                     | Patched TRE                                       | Pending                                   |
| Balance/code/storage mutation and impersonation                | Scope account state and translate only verified native methods                                                                    | Patched TRE                                       | Pending                                   |
| Revert/event/balance matchers                                  | Adapt assertion registration and connection lookup without global HRE/module patching; list accepted assertions                   | Ordinary/patched TRE according to assertion       | Pending                                   |
| Compiler include/exclude and batches                           | Preserve source-selection intent through public H3 build/task facilities; reject unsupported combinations explicitly until tested | Verified compiler                                 | Pending                                   |
| Metadata and node instance identity                            | Per-node identity and request handling; no global provider or stale manifest identity                                             | Ordinary/patched TRE according to identity method | Pending                                   |
| EVM coexistence and multiple TRON connections                  | Isolate providers, accounts, artifacts, receipts, helpers and cleanup ownership                                                   | EVM plus ordinary TRE                             | Pending                                   |
